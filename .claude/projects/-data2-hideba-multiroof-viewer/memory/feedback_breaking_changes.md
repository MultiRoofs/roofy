Breaking changes are fine in this project. Prioritize well-organized code and good UI/UX over keeping backward compatibility.

**Why:** The project is experimental/prototype stage — no production consumers to break.

**How to apply:** Don't hesitate to refactor APIs, change Canvas settings, restructure components, or remove deprecated patterns when it improves code quality or UX. No need for migration shims or backward-compat hacks.
